# Prespecified statistical analysis plan

Experimental unit: one architecture × scenario × paired input variant × repetition in an isolated API process and SQLite file. Architecture is the main factor. Fix provider, exact model/version, endpoint, inference controls, host class, scenario inputs, tool implementation, and pricing source. Randomize architecture order within each scenario/variant block with a recorded seed; rotate order across blocks. Analyze simulated plumbing, real model behavior, and fault/reliability trials separately.

Primary measures: independently observed scenario success (intended committed effect and policy condition) and scenario execution latency among verifiable runs. Report per-scenario and overall successes with numerator, attempted denominator, unverifiable count, and Wilson 95% confidence intervals. Also report a sensitivity analysis treating unverifiable runs as failures. For paired variants compare binary outcomes with paired differences and confidence intervals; use McNemar only when pairs are complete. For latency report mean, median, nearest-rank P95, standard deviation and interquartile range by architecture/scenario, with bootstrap intervals resampling paired blocks. Provider outages and infrastructure failures are tabulated separately and never silently excluded.

Secondary measures: interaction turns, LLM requests, input/output tokens, argument-collection calls, business-tool attempts, duplicate committed effects, confirmation violations, and recovery success among recovery-eligible runs. Each measure reports observed denominator; missing tokens remain missing. Examine paired differences rather than treating repeated scenario variants as independent. Control familywise error for three primary architecture contrasts with Holm adjustment; secondary findings are exploratory with effect sizes and intervals. Report both improvements and regressions. No significance claim follows from descriptive summaries alone.

Thirty repetitions per architecture/scenario yield at most 30 paired observations and wide binary intervals, especially near zero failures. Use a small pilot solely to estimate variance, failure rate, and token range; determine final repetitions from a prespecified minimum important difference or interval-width target before collecting confirmatory results. Do not stop early for a favorable result. Stop for safety limits, provider outage, or protocol deviation, preserve partial results, and record reasons and timestamps.
